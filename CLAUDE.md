# NeoEssentials — форк ZeroG-Network-PTY-LTD/NeoEssentials

Серверный мод «эссеншелов» для Minecraft 1.21.1 / NeoForge 21.1.179. Сабмодуль монорепо
Farmstead, собирается как подпроект `:neoessentials` реактора `game/`.

| | |
|---|---|
| Наша ветка | `farmstead-monorepo-build` (`origin` = shtanko-michael/NeoEssentials) |
| Апстрим | `upstream/1.21.x` — единственная ветка апстрима, оставшаяся на MC 1.21.1 |
| Не синкать | `26.1.x` (MC 26.1.2) и `26.2.x` (MC 26.2) сломают сервер; `Released` — только документация |
| Сборка | `cd ../ && ./gradlew :neoessentials:jar` (или `npm run game:build-dev` из `runner/`) |
| Документация | https://shtanko-michael.github.io/NeoEssentials/ |

## Документацию обновляем в той же задаче, что и код

Любое изменение, которое добавляет, переименовывает или удаляет **команду, узел прав, ключ
конфигурации или пользовательскую строку**, обязано обновить сайт документации — не «потом».

Генерируется из исходников, править руками не нужно:

- таблицы команд (из `registerCommand` / `registerCommandWithPermission`);
- узлы прав (из `PermissionRegistry`);
- ключи конфигурации (из `src/main/resources/data/config/neoessentials/*.json` — комментарий
  `//` над ключом и есть его описание, так что документируйте ключ прямо в конфиге);
- покрытие языков (из `src/main/resources/data/lang/*.json`).

Пишется руками, обновлять обязаны вы — **на двух языках сразу**:

- `docs/site/content/systems/<slug>.json` — `commands`, `commandDetails.syntax`, `examples`,
  `edgeCases`, `knownIssues`;
- `docs/site/content/systems/<slug>.md` — пояснительный текст, если руководства апстрима мало;
- `docs/site/content/_meta.json` — при появлении новой системы;
- английский двойник каждого из них — `docs/site/content/en/<тот же путь>`.

Сайт двуязычный: русский в корне, английский под `/en/`, переключатель RU/EN в шапке
запоминается в браузере (`localStorage` `ne-docs-lang`, как тема), первый визит — по языку браузера.
Русский текст — эталон. Английский JSON накладывается поверх русского (словарь — по ключу, список —
по индексу), поэтому в `content/en/*.json` та же структура, переведены только строки; команды, узлы
прав, ключи конфига, `syntax` и фиксированные якоря (`#komandy`, `#primery`, `#konfiguraciya`,
`#prava`, `#podrobnoe-rukovodstvo`, `#tonkie-mesta`, `#izvestnye-problemy`, `#cmd-*`) не переводятся.
Нет английского файла — сборка берёт русский и пишет предупреждение, а `--strict` падает.
Подписи интерфейса сайта — словарь `UI` в `generate.py` (пара «ru, en» на ключ).

Проверка перед завершением задачи:

```bash
python docs/site/generate.py --strict   # должен выйти с кодом 0
```

`--strict` падает, когда кураторский контент ссылается на несуществующую команду или доку —
это и есть сигнал о расхождении. Публикация сайта автоматическая: `.github/workflows/wiki.yml`
пересобирает GitHub Pages на каждый push в `farmstead-monorepo-build`.

Вкладка GitHub Wiki — только оглавление со ссылками на сайт. После изменения списка систем
в `_meta.json` пересоберите индекс и залейте его в `NeoEssentials.wiki.git`:

```bash
python docs/site/generate.py --strict --wiki-out docs/site/_wiki
```

`docs/Wiki/` — каталог апстрима. Он встраивается в сайт как есть и **не редактируется здесь**,
иначе следующий синк с апстримом даст конфликты. Свой текст — только в `docs/site/content/`.
Генератор живёт в `docs/site/`, а не в `docs/wiki/`: на Windows это одно и то же имя папки.

### Сайт документирует несколько модов Farmstead

Корень сайта — лендинг «Моды Farmstead», обзор NeoEssentials — `/neoessentials/`, остальные его
страницы на прежних адресах. Вкладки в шапке задаёт `docs/site/content/_products.json`; разделы
`claims/` (Farmstead Claims, со старых `/regionguard/` — редиректы), `aibuilder/` (Farmstead
AI Builder) и `utilities/` (Chunk Breeding Limit, Trade Chat) рендерит один общий код по их
`_meta.json` (страницы, группы навигации, заголовки, леды, ключевые слова поиска).

**Эти разделы — копии собственной документации модов** (`game/claims-mod`, `game/ai-builder-mod/publish`,
`game/chunk-breeding-limit-mod`, `game/trade-chat-mod` в монорепо). Pages собирается из одного
этого репозитория, поэтому при сборке ничего не читается из соседних модов. Изменились команды,
конфиг или тексты такого мода — обновите его раздел здесь **на двух языках в той же задаче**
(`content/<раздел>/` и `content/en/<раздел>/`), сверив команды и ключи с исходниками мода.

## Локализация

Русский — язык сервера Farmstead (`localization.language` в его `config.json`; в поставке — пусто,
то есть `en_us`). **Все девять языковых файлов всегда полные**: `en_us` — эталон, и любая
добавленная, переименованная или удалённая пользовательская строка в той же задаче попадает во
все `data/lang/*.json` — `ru_ru`, `de_de`, `es_es`, `fr_fr`, `nl_nl`, `pl_pl`, `pt_br`, `zh_cn`.
Удалённый ключ удаляется из всех файлов, переименованный — переносится с переводом.

Проверка — `python tools/lang_check.py` (код 1 при ошибке; `--lang de_de` — один язык,
`--untranslated` — ещё и значения, совпавшие с английским). Она же встроена в
`docs/site/generate.py --strict`, так что неполный перевод роняет сборку сайта. Жёсткие ошибки:
нет ключа, лишний ключ, другой набор плейсхолдеров `{0}`/`{name}`/`%s`, другие теги
`<gradient:…>`, другое число `\n`. Расхождение цветовых кодов — предупреждение: порядок
слов законно двигает цвета, но прочитайте его. Плейсхолдер, которого нет в коде вызова, не
«чинится» копированием из английского — сверяйтесь с аргументами в Java.

При синке с апстримом языковые файлы конфликтуют чаще всего: берите новые ключи апстрима, наши
переводы оставляйте, затем прогоните `lang_check.py` и допереведите то, что апстрим добавил.

В переводе обязаны сохраняться: коды `§x` (все, в том же порядке), плейсхолдеры `{0}`/`{1}`/`%s`,
именованные плейсхолдеры и теги `<gradient:…>`, литеральные `\n` и краевые пробелы. Подстановка —
простая замена (`MessageUtil.applyArgs`): `''` становится `'`, одиночная кавычка безопасна.

Не переводятся: литералы команд, имена аргументов в `<>`/`[]`, узлы прав, ключи и пути конфигов,
названия модов.

## Синк с апстримом

Перед мёрджем — резервная ветка и тег в сабмодуле: синк 2026-09-12 дал 67 конфликтных файлов и
258 хунков. Правило разрешения: код принадлежит апстриму, форк сохраняет своё осознанное
поведение. Сознательные расхождения форка описаны в комментариях по месту — не «чините» их
обратно под апстрим, не прочитав комментарий.

Реактор монорепо требует двух вещей, которых нет в отдельном чекауте апстрима: подпроект
`vault-api` смонтирован в `game/settings.gradle` по тому же пути `:vault-api`, а `:neoessentials`
объявлен зависимым от него через `evaluationDependsOn`.
