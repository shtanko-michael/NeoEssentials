## Как пользоваться этой страницей

Ниже собраны известные проблемы со всех систем: симптом, каким его видит администратор, затем
причина и что с этим делать. Каждая запись выверена по исходникам, `Issues_Discovered.md` или
записям «Fixed» в чейнджлоге — сюда не попадают предположения.

Записи сгруппированы по системам; на странице самой системы они же продублированы в конце, рядом
с её командами.

## Сначала проверьте это

Три причины покрывают большую часть обращений «команда не работает»:

1. **Подсистема выключена.** Секции `modules` и `commands` в `config.json` читаются один раз при
   старте сервера. Если команда там выключена, её просто нет в реестре — `/help` её не покажет, а
   сервер ответит как на неизвестную команду. `/neoessentials reload` тут не поможет, нужен
   перезапуск.

2. **Нет права, а не поломка.** Команда, на которую нет узла, не видна в `/help` и ведёт себя как
   несуществующая. Проверьте реальный узел в колонке «Право» на странице
   [Все команды](../commands/index.html) — он может не совпадать с шаблоном
   `neoessentials.<имя команды>`.

3. **Правку конфига не перечитали.** `/neoessentials reload` обновляет значения, но не состав
   команд и не уже открытые GUI. После правок в `modules`, `commands` и вообще после смены
   структуры конфига нужен перезапуск.

## Если нужно больше подробностей

Включите подробное логирование для конкретной подсистемы — не глобально, а точечно:

```json
"logging": {
  "categories": {
    "TELEPORTATION": { "normal": true, "debug": true }
  }
}
```

Отладочный вывод пишется в `logs/debug.log`. Категории и их назначение — на странице
[Логирование](../systems/logging/index.html).
