Все команды начинаются с `/rg`. Не-оператору обычно требуется базовая нода `regionguard.command` вместе с нодой конкретной подкоманды. Для нод модерации `regionguard.admin.*` это не требуется: каждая открывает только соответствующую ей операцию.

## Возврат гостя на спавн

`/bb <player>` доступна владельцу или участнику привата, в котором он сейчас стоит, а также модератору с `regionguard.admin.access`. Указанный онлайн-игрок тоже должен находиться в этом же привате. Если он не числится ни владельцем, ни участником этого привата, RegionGuard немедленно отправит его на настроенный серверный spawn и покажет ему сообщение «Вас выгнали из региона». Обычный warmup и сообщения команды `/spawn` не используются. Для владельца и участника привата команда ничего не делает.

## Управление регионами

| Команда | Назначение |
|---|---|
| `/rg define <id>` | Создать регион по текущему выделению. Игрок становится владельцем. Алиас: `/rg claim <id>`. |
| `/rg redefine <id>` | Перенести границы существующего региона на новое выделение, сохранив владельцев, участников и флаги. |
| `/rg remove <id>` | Удалить регион. Алиас: `/rg delete <id>`. |
| `/rg list` | Показать регионы текущего измерения, которыми игрок владеет. OP, консоль и `regionguard.admin.list` видят все регионы. |
| `/rg info [id]` | Без `id` показать доступные регионы; с `id` открыть подробную карточку региона. |
| `/rg tp <id>` | Безопасно телепортироваться к центру региона. |

`define`, `redefine` и `remove` недоступны для системного региона `__global__`. Размер нового выделения проверяется до записи: сумма длин по X, Y и Z не должна превышать 384 блока.

## Владельцы и участники

| Команда | Назначение |
|---|---|
| `/rg addowner <id> <player>` | Добавить владельца по нику, UUID или кэшу профилей. |
| `/rg delowner <id> <player>` | Удалить владельца. Последнего владельца удалить этой командой нельзя. |
| `/rg clearowners <id>` | Удалить всех владельцев. |
| `/rg addmember <id> <player>` | Добавить участника. |
| `/rg delmember <id> <player>` | Удалить участника. |
| `/rg clearmembers <id>` | Удалить всех участников. |

Состав региона может менять только его владелец, OP уровня 2 или игрок с `regionguard.admin.members`. Участник может пользоваться приватной территорией, но не управлять ею.

## Флаги

| Команда | Назначение |
|---|---|
| `/rg flag <id> list` | Открыть интерактивную панель доступных булевых флагов. |
| `/rg flag <id> <flag> <value>` | Установить значение флага. |
| `/rg flag <id> clear <flag>` | Сбросить флаг целиком к значению по умолчанию. |
| `/rg flag <id> clear <flag> <value>` | Удалить одно значение из флага-множества. |

Панель `list` показывает только булевы флаги, для которых выдано `regionguard.command.flag.<flag-id>`. Игрок с `regionguard.admin.flags` видит и меняет все флаги. Строковые флаги и множества задаются прямой командой.

## Значения сложных флагов

`mobspawning` — командный алиас флага `mob-spawning` со специальным синтаксисом:

```text
/rg flag <id> mobspawning allow-only <entity_id>
/rg flag <id> mobspawning deny-only <entity_id>
/rg flag <id> mobspawning allow <entity_id>
/rg flag <id> mobspawning deny <entity_id>
```

Эффект маяка добавляется в виде эффекта и уровня от 1 до 5:

```text
/rg flag spawn beacon speed 3
/rg flag spawn beacon resistance 2
```

Для `interact-allow`, `interact-deny`, `chest-access-allow` и `chest-access-deny` передаётся ID блока или сущности, например `minecraft:chest` или `minecraft:villager`.

## Автодополнение

Аргументы региона и флага поддерживают подсказки Brigadier. Для значений предлагаются подходящие варианты: `allow`/`deny`, режим погоды, эффекты маяка и известные идентификаторы.
